Your agent already ran the tests. Let that run be the check.

shipcheck runs your GitHub Actions workflows on your machine, keeps the result for that exact git tree, and posts the required check. A PR whose tree was already tested gets its check in under a second.

$ brew install gabrielkoerich/tap/shipcheck
$ curl -fsSL https://shipcheck.run/install.sh | sh
$ cargo install shipcheck
$ cargo install --git https://github.com/gabrielkoerich/shipcheck shipcheck

Then run shipcheck init in your repository. Quickstart

The CI of bean, a private Python repository of the author's, on the same commit. shipcheck ran on an Apple silicon Mac with Docker Desktop, GitHub on its hosted runners. How it was measured. A single run can take longer than on GitHub. The gain is no runner queue, no Actions minutes on PR pushes, and no new run for a tree already tested.

How it works

  1. The agent commits and pushes. A git hook starts shipcheck in the background for that commit. Nothing waits, and a newer commit stops the older run.
  2. shipcheck reads what to run from main. shipcheck.toml and the workflows come from origin/main, never from the branch, so a PR cannot change what checks it.
  3. It runs the workflows in a warm, clean checkout. A copy-on-write clone of the commit keeps the build caches, act runs the jobs in Docker, and markers added to shipcheck's own copy of each workflow report every job.
  4. It keeps the result for the tree. The key is the git tree plus the config and runner versions, so a rebase or a squash with the same tree needs no new run.
  5. The PR gets its check. shipcheck posts the result as the required shipcheck check. GitHub still runs your workflows on main after the merge.

What the repository owner sets up

One file says which workflows a PR must pass. Your workflows stay as they are.

# shipcheck.toml
workflows = ["ci.yml"]
on = ["push", "commit"]
paths = ["src/**"]
  • shipcheck init writes the file and installs the hook.
  • A GitHub App posts the check. Today you register your own, a one-click shipcheck App is coming. What works without it
  • A ruleset requires the check on main, so a PR merges only after it passes.
  • Each teammate runs shipcheck install once per clone.

What it stops, and what it does not

It stops

  • An agent that reports a pass it never ran. Only shipcheck posts the check, from runs it started.
  • A PR that edits its workflows or shipcheck.toml to skip work.
  • A pass from before main's config changed.
  • A pass from files that were never committed.

It does not stop

  • An agent that deletes or weakens a test. Tests are part of the PR, so review them.
  • Differences between act and GitHub's runners. The hosted run on main catches them.
  • Jobs act cannot run, such as macOS jobs without a Mac, or a job that mounts a loop device.

Status

Early. Local runs, the cache, the background hooks and posting the check with your own GitHub App work today. A one-click hosted GitHub App is coming.
